# pair-wise-yf-58 功能开关和灰度发布控制台

## 源提示词摘要
产品负责人配置目标用户、地区、应用版本和依赖条件，研发负责人审批发布计划，值班人员观察过程并随时关闭开关。系统支持规则组合、流量逐步增加、定时生效、紧急停止、回滚，并能在保存前模拟不同用户的命中版本。

## 技术栈
Vue 3 + TypeScript + Vite + Ant Design Vue + Pinia + Vue Router + Axios + VueUse + VeeValidate + Zod + Vue I18n。

## 已实现闭环
- 功能开关、发布计划、审计记录三类业务对象。
- 规则组合、模拟用户命中、逐步调整流量和定时生效。
- 产品/研发双审批、开始灰度、紧急停止、回滚和恢复草稿。
- 离线提示、VeeValidate + Zod 精确校验和 localStorage 持久化。

## 实验层（开关接入层）
解决多个灰度开关各自放量时：相互冲突的实验被同一人命中、层名额超出、无全局卡点的问题。

**核心规则**（实现见 `src/experiment/engine.ts`）：
- **开关接入层**：开关挂在层内实验上，实验带权重与定向（地区/最低版本/登录要求）。
- **层内互斥**：同一用户在同一层至多占住一个实验（FNV-1a 稳定哈希分桶，桶号只取决于层盐+用户ID，规则改动不变桶）。
- **层容量上限**：每层 `capacity`；实验也可单独设 `capacity`；满了进**排队队列**，记录 `experiment_full / layer_full / global_full` 原因，名额放开后**按登记先后递补**。
- **不同层独立**：同一人允许在多个层同时命中。
- **全局名额**：按**去重用户数**卡（同人多层命中只占 1 个全局名额）。
- **规则改动重算**（`changeRules`）：旧占位全部作废；第一批先按登记先后安置所有旧占住者（保留/改投/退出），第二批再按登记先后处理排队者与未命中者；保留不下的按登记先后退出，原因写明：
  `targeting_mismatched`（定向不再匹配）、`no_enabled_experiment`（开关全关）、`layer_full`（层缩容）、`global_full`（全局缩容）、`layer_removed`（层被删除）。
- 所有重算动作写审计；状态可用 `snapshot()/restore()` 持久化（控制台存 localStorage）。

**终端模拟**（四幕，输出每个用户命中的层/实验/桶号、排队与退出原因）：
```bash
npm run sim
```
1. 旧模式复现：开关各算各的，互斥实验同人同时命中、名额失控；
2. 接入层放量：互斥、层/实验/全局容量、排队；
3. 规则改动：缩容+关开关+收紧定向+新层，旧占位作废、保留/改投/退出逐条列原因；
4. 只放开名额：排队者严格按登记先后递补，零误驱逐。
